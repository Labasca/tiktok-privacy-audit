What TikTok reads, and what our rig still misses

We stopped guessing which APIs to hook. This dossier covers two layers. The data layer (what TikTok reads about your device) is cross-checked against three sources of truth, including TikTok's own on-device privacy declarations. The behavioral layer (how you touch and scroll, and whether a real finger is driving) is enumerated from the anti-automation research and mapped to a safe build order.

04 The ten gaps, ranked by risk to add

Every gap is a real fingerprinting vector, but they are not equal to hook. Ordered so we can add the safe ones first, exactly as before.

Safe to add nowcold ObjC reads, same class as existing hooks · zero freeze risk
  • URL credential store   NSURLCredentialStorage.allCredentialsSaved HTTP credentials, one cold call. objection surfaces this.
  • Free disk space   attributesOfFileSystemForPathThe ObjC way to read free space. TikTok declares the disk-space category via 13 modules.
  • Volume capacity keys   resourceValuesForKeys:The modern NSURL free-space path, same declared category.
  • File timestamps via ObjC   attributesOfItemAtPathCreation / modification dates. TikTok declares file-timestamp use via 16 modules.
  • Contacts read   CNContactStore.enumerateContactsFires when contacts are actually read, not just the permission check we already have. TikTok declares Contacts collection.
Moderate · needs a self-detaching hotHooknative, on the hot path · sample then detach, like getifaddrs
  • statvfs family   statvfs / fstatfs / fstatvfsNative disk-space siblings of statfs. Can be called in loops, so sample and self-detach.
  • getattrlist family   getattrlist / getattrlistbulkThe currently-excluded file-metadata call. Hottest of the set, worth it only behind a strict hotHook cap.
  • Crypto material   CCCrypt / CCCryptorUpdateKeys, IVs, and plaintext passing through CommonCrypto. High signal, high volume, sample only.
Skiplow value for the freeze risk it carries
  • Monotonic clock   mach_absolute_time()One of the hottest functions in the process and boot time is already covered by systemUptime and sysctl. Not worth the exposure.

06 The behavioral layer: how you touch, not what you are

None of this appears in privacy manifests, because Apple does not class it as data collection. It is input provenance and anti-automation: whether a real finger drives the feed, how you flick, and whether the runtime is instrumented. It is grouped into build waves by the one thing that matters here, freeze risk. All three waves are now implemented and verified in a clean 25-second run, no freeze, all kill layers idle.

source: 25s safe-mode run · observe.js

On launch alone, before any scrolling, TikTok asked MobileGestalt for 16 device keys. Several are plaintext, model and region and IsSimulator and apple-internal-install (an emulator / non-retail tell). Several more are obfuscated hash keys, which is exactly how the sensitive identity and anti-tamper values (serial, UDID, production status) are addressed.

Wave 1 · safe cold readsone-shot getters, same class as current hooks · zero freeze risk
  • Accessibility bitmask   UIAccessibilityIs*Running / *EnabledAll 15 flags in one cold loop. AssistiveTouch and VoiceOver are the automation tells, the rest is fingerprint entropy.
  • Device attribute stream   MGCopyAnswerLog every MobileGestalt key TikTok pulls: UDID, serial, IMEI, WiFi/Bluetooth MAC, model, region, SigningFuse, and its Developer Mode probe. The single highest-value new hook. Budgeted so a launch burst cannot run away.
  • Screen capture & mirroring   UIScreen.isCaptured, screenshots, external displayIs the feed being recorded, mirrored, or screenshotted, and is a second display wired in.
  • Connected peripherals   GCMouse.mice, GCKeyboard, GCController, EAAccessoryManager, CBCentralManagerExternal mouse, keyboard, controller, MFi hardware, or Bluetooth reach. A mouse or keyboard driving a phone feed is a strong automation-rig signal.
  • Physical context   proximityState, orientation, UIScreen.brightness, haptic hardware classHeld to the face, held upright vs flat on a table, ambient-light proxy, and whether a real Taptic Engine exists.
  • Anti-tamper environment   getenv(DYLD_INSERT_LIBRARIES), dyld image scan, Frida-port / thread-name checks, csops, entitlements, sysctl(KERN_PROC)Everything TikTok reads to detect jailbreak, injection, and debugging. We log and pass through, never neutralize.
Wave 2 · hot, self-detaching hotHookthe finger-vs-synthetic core · sample then detach, like getifaddrs
  • Touch provenance   one interpose on -[UIApplication sendEvent:]Every UIEvent passes here once. Read UITouch.type (Direct finger vs IndirectPointer mouse/trackpad vs Stylus), whether _hidEvent is non-null, and whether coalescedTouchesForTouch: is non-empty. Those three catch the majority of injected/synthetic input. This is the direct answer to "is a real finger driving the swipes."
  • Flick dynamics   UIPanGestureRecognizer.velocityInView:, scroll delegateThe velocity and overshoot curve of each swipe. Humans vary it, scripts repeat it. Sampled, not streamed.
  • Engagement haptics   UIImpactFeedbackGenerator, notification / selectionIntercepting the haptic calls hands us TikTok's own taxonomy of "moments" (like, snap, error) for free.
Wave 3 · optional hot sensor samplinghigh signal, highest volume · sample a handful then detach
  • Hand tremor & hold angle   CMDeviceMotion.attitude / userAccelerationReal hands micro-jitter, a perfectly static rig does not. We already log that TikTok starts the stream, this would sample a few live values.
  • Live barometer   CMAltimeter pressureAmbient pressure micro-fluctuations are one of the hardest live-hardware signals to fake. Sample only.

One read-only caveat: two anti-tamper calls, ptrace(PT_DENY_ATTACH) and its raw-syscall twin, actively block instrumentation rather than read state. We observe that TikTok calls them and pass through. We never neutralize them, which keeps the rig honest and read-only even though it means accepting whatever defense TikTok mounts.
